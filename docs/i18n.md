# Internationalization (i18n)

The Windows client has **two independent i18n halves**, because its UI is rendered
by two processes:

| Surface | Owner | Mechanism |
|---|---|---|
| Renderer UI (all `@phlix/ui` screens, shell, palette, player…) | `@phlix/ui` | config-time override seam: `createPhlixApp({ messages })` |
| Main-process chrome (tray, app menu, thumbar tooltips, updater notifications, About dialog) | this repo | local catalog + `t()` in `src/main/i18n/` |

Only English ships today; both halves are wired so a new locale is additive-only.

## 1. Renderer — the `@phlix/ui` message seam

`@phlix/ui` ships `DEFAULT_MESSAGES` (~407 keys, two-level `group.key`) and accepts
`PhlixAppConfig.messages?: PhlixMessagesConfig` — a **deep-partial override map**.
Omitting the key (or an empty map) renders the shared English UI byte-for-byte
unchanged; merging is per-group, so unlisted strings fall back to ui's defaults.
Translation of `{name}` placeholders and pipe-plurals happens inside ui
(`createTranslator` / `useMessages().t`).

This client resolves *which* override map to send in `src/renderer/i18n/`:

```
priority: VITE_PHLIX_LOCALE (build-time env) → navigator.language → 'en'
```

- `resolveLocale()` — the chain above (`pickLocale()` is its pure, testable core).
- `messagesForLocale(locale)` — registry lookup (exact tag, then base language,
  e.g. `es-MX` → `es`). Returns `undefined` when the locale has no non-empty
  override map, and `src/renderer/main.ts` then **omits** `messages` from the
  config entirely. This is what keeps today's shipped app byte-identical.
- `src/renderer/i18n/overrides/en.ts` — Windows-specific English tweaks (none
  today; ui's defaults are authoritative).

### Adding a renderer locale

1. Author `src/renderer/i18n/overrides/es.ts`:

   ```ts
   import type { PhlixMessagesConfig } from '@phlix/ui';
   export const esOverrides: PhlixMessagesConfig = {
     shell: { browse: 'Explorar' } // only the strings you translate; the rest stay English
   };
   ```

2. Register it at the bottom of `src/renderer/i18n/index.ts`:

   ```ts
   registerLocaleOverrides('es', esOverrides);
   ```

3. Users/selectors get it via `VITE_PHLIX_LOCALE=es` or an `es-*` system language.

## 2. Main process — local catalog + `t()`

Main-process strings never touch the Vue app, so they live in
`src/main/i18n/en.ts` — a two-level `group.key` catalog mirroring ui's shape —
resolved by the pure, electron-free `t()` in `src/main/i18n/index.ts`.

**Ready-ordering:** `app.getLocale()` requires the Electron `ready` event. The
locale is therefore pinned **once** at the top of the `app.whenReady()` callback
(before `createWindow`/`createMenu`/`createTray`), and every string builder
(menu, tray, thumbar, updater notifications, About dialog) runs after that point.
`buildPlaybackMenuTemplate()` is a function (not a module-scope const) precisely
so its labels are evaluated post-ready. Role-based menu items (`role: 'quit'`,
`role: 'reload'`, …) intentionally keep no label — Electron renders roles with
native, already-localized strings.

`tests/unit/mainI18n.test.ts` pins every extracted value against the literal that
was hardcoded before the extraction — an accidental wording change goes red.

### Adding a main-process locale

1. Author `src/main/i18n/es.ts` typed as `MainCatalog` (derived from `en`, so a
   missing key is a **compile error**):

   ```ts
   import type { MainCatalog } from './index';
   export const es: MainCatalog = { tray: { show: 'Mostrar Phlix', /* …all keys… */ } , …};
   ```

2. Add one registry entry in `src/main/i18n/index.ts`:

   ```ts
   const catalogs: Record<string, MainCatalog> = { en, es };
   ```

   `setMainLocale('es-MX')` then matches by exact tag, else base language, else
   falls back to English.

## What is NOT localized here

- **Log lines** (`log.info` etc.) — developer-facing, intentionally English.
- **Renderer smoke / menu labels built in `src/renderer/main.ts` `buildMenu()`** —
  these are `MenuItem` labels *supplied to* ui's shell; adopt them through the ui
  seam upstream if a shared key appears.
- **IPC notification payloads** (`notification:show`) — strings come from the
  renderer (i.e. already inside ui's seam or page-local copy upstream).
- Deep-link error dialogs (`showErrorDialog`) — operator diagnostics.

## Test pins

- `tests/unit/mainI18n.test.ts` — catalog ↔ original-literals equality, interpolation,
  locale fallback, fail-loud unknown key.
- `tests/unit/rendererI18n.test.ts` — `pickLocale`/`resolveLocale` priority, registry,
  and the real `@phlix/ui` merge semantics (`createTranslator`/`mergeMessages`).
- `tests/unit/i18nSeamWiring.test.ts` — boot() passes the resolved map as
  `config.messages` and omits the key when there is nothing to override.
